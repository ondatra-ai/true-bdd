# Go Conventions

**Three channels, one package each, held by banning identifiers and imports**: the split is ANSWER versus NARRATION, not who reads it. `pkg/console` is an answer — bytes a caller reads verbatim in a shape it fixed (the lint hook's JSON verdict, a gate's report that `lint.Hook` captures into that verdict) plus the engine's prompts and the reader they are answered on; that is why it stays byte-plain and why it, not `os`, owns the three descriptors, so a subprocess's `cmd.Stdout` is wired to `console.Out()`. Everything a program says about its own run is `pkg/logging`, which is `log/slog` and nothing else: the text stream is bound per program in `main()` — the engine binds stdout, because 22 steps in `docs/scenarios.yaml` assert `stdout matches level=ERROR` and there is no `stderr matches` step at all — and every `scripts/` program also appends to the Task's shared log under `docs/history/task_logs/`, each record carrying `tool` and `run`. One shared file is safe because `logging` writes one `disk.Append` per record and `disk` holds the PARENT directory for it; `state.TaskLog` names it from the `log` key, which `state.Init` drops, so the log lives one Task and the previous one survives on disk. `run` is a per-process id and is what makes the shared file parseable — merge's fix agents spawn `gates` as a SEPARATE process into the same file, so `scripts/report` filters to one `run` before folding or the tree is corrupt, not merely cluttered. `logging.Install` still creates the file up front — E2E-019 reads an engine log with zero records, so a missing one is not an empty one; the no-Task fallback is therefore a NAMED `no-task.json` rather than a random stem, or every fresh Task would strand one. The engine passes no `tool`, which keeps its log shape provably unchanged — its message strings and attribute keys are frozen, since `tests/libraries/reporter` folds turns on seven exact messages and renaming one breaks the report with nothing going red. `pkg/disk` is every filesystem read *and* write, each a short `flock` on the target's parent around open-do-close, whole-file writes via temp+rename (`docs/adr/0003`). Gotcha with teeth: `disk` wraps its errors, and `os.IsNotExist` does not unwrap — an absent file is `errors.Is(err, fs.ErrNotExist)` now, and the old check silently reports false. The gotcha that shapes the gate: **forbidigo matches identifiers, never call expressions** — it never sees an argument, so banning `os.Stdout|Stderr|Stdin` is what catches `cmd.Stdout = os.Stdout` and makes banning `fmt.Fprint*` unnecessary, leaving `fmt.Fprintf(&buf, …)` string building untouched. `depguard` carries the rest: stdlib `log` as `pkg: "log$"` (the `$` is load-bearing, since depguard matches by prefix and a bare `log` would deny `log/slog`), and `pkg/console` denied to `scripts/**` outright — five files are exempt and each holds a descriptor, not a print: the hook's stdin and JSON verdict, and three that wire a child's streams. Four more lists hold the SHAPE of the tree rather than a channel: `hex-domain` (the domain imports neither `infrastructure`, `app`, `adapters`, `claudecode` nor `cmd` — a port that names its own implementation is a seam that breaks nothing), and `root-pkg-floor`/`root-services`/`root-scripts` (`pkg/` imports no root, product code imports neither the tooling nor the tests, tooling shells out to the binary rather than linking it). Go's own `internal/` rule already blocks part of that by accident, which is why the tree was clean; the lists cover what it does not. `root-pkg-floor` negates `**/services/**` because `**/pkg/**` also matches `internal/pkg/errors`, which is not the floor. What golangci-lint cannot reach at all, `.alint.yml` does: it is text-level and tag-blind, so it sees the `// Code generated` files `generated: lax` skips and the sentinel-fenced trees `./...` never lists. `pkg-is-the-declared-channels` allowlists the four packages `pkg/` may hold, so the fourth root cannot become a parking lot. `go-no-platform-filenames` bans a GOOS/GOARCH filename suffix and `go-no-legacy-build-tag` the pre-1.17 `// +build` — each hides a file from every Go gate with no tag for `go-build-tag-allowlist` to catch, verified by a planted `*_windows.go` that drew zero issues from golangci-lint while compiling into the binary. Deliberately unbanned: `os.Stat`/`os.ReadDir`/`os.Symlink`, which move no bytes. Where the gate cannot reach: the `bdd`-tagged tree (`tests/*/scenarios/`) and the sentinel-fenced trees, which golangci-lint does not analyse at all — those were converted by hand and nothing stops them drifting back. Everything else is an inline `//nolint:forbidigo` carrying its reason: SQLite's own files, an flock fd inherited by a child, and the two handles that must outlive their call (the spawn tee, the subprocess stderr spill).

**Single entity, single file**: each Go file holds one primary entity, filename = entity name in snake_case (`GitHubService` → `github_service.go` — "GitHub" is one word). Acceptable exceptions: function/constant-only files, re-export files, closely related types, data structures bundled with their primary entity. The casing is gated (`.alint.yml`, `go-filename-snake-case`); the one-entity rule is still review.

**The ceilings are numbers, not taste** (`.golangci.yaml`, ~100 linters on `default: standard`): a function is ≤80 lines and ≤40 statements (`funlen`), cyclomatic complexity ≤10 (`cyclop`; `gocyclo` is on but unconfigured, so its default 30 never binds first). Split at the ceiling rather than arguing with it. Also on and worth knowing before you write: `gochecknoglobals` and `gochecknoinits` (no package-level `var`, no `init()` — a global needs a `//nolint:gochecknoglobals` with a reason), `mnd` (name the magic number), `varnamelen` (no `x` living twelve lines), `nonamedreturns`, `testpackage` (tests go in `package foo_test`), `exhaustive` (a switch over an enum names every case).

**Errors have three rules that interlock**: `errors.New` for a static message, `fmt.Errorf` with `%w` to wrap — `err113` forbids the middle case, a `fmt.Errorf` with no argument to interpolate. (A `forbidigo` pattern claimed that job for a long time and never once fired: forbidigo cannot see a call's arguments. It is gone.) `wrapcheck` wants every error crossing a package boundary wrapped, and exempts `internal/pkg/errors` because that package already wraps. `err113` (no dynamic errors) is lifted in `_test.go`, where fixtures make them freely.

**Struct tags are snake_case both ways** (`tagliatelle`: `json: snake`, `yaml: snake`) — except where the casing is somebody else's wire contract, which is what the three carve-outs in `.golangci.yaml` mark: `adapters/github/`, `models/thread.go` (GitHub's camelCase API) and `infrastructure/testrunner/dto/` (`go test -json` PascalCase, `jest --json` camelCase). Match the wire there, not us.

**Whitespace is linted, and fixable**: `wsl_v5` (cuddling rules — first statement in a block may cuddle, a branch body up to 2 lines may) plus `nlreturn` (blank line before `return`). Never hand-fix these — `go run ./scripts/cmd/lint <file>.go` runs `golangci-lint --fix` over the whole package and rewrites them, which is also what the PostToolUse hook does on every edit.

**Comment budget** (`scripts/lint`, tested): ≤3 lines of prose, ≤15 of indented block scheme. Prose is argument and compresses; a comment earns length only by carrying a fact learned by observation — one a simplifier would delete with no gate going red — and that fits in a line plus its provenance (PR #, comment id). State each fact once, at the line it guards; the narrative goes to `docs/for_further/`. Exempt from the prose cap only: the doc comment preceding `package X`, which `go doc`/gopls surface on every lookup.
