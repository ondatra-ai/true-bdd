# Go Conventions

**Four channels, one package each, held by banning identifiers and imports**: the split is ANSWER versus NARRATION, not who reads it. `pkg/console` is an answer — bytes a caller reads verbatim in a shape it fixed (the lint hook's JSON verdict, which `pkg/claude/hooks` writes, and a gate's finding, which `pkg/alint` does) plus the engine's prompts and the reader they are answered on; that is why it stays byte-plain and why it, not `os`, owns the three descriptors, so a subprocess's `cmd.Stdout` is wired to `console.Out()`. Everything a program says about its own run is `pkg/logging`, which is `log/slog` and nothing else: the text stream is bound per program in `main()` — the engine binds stdout, because 22 steps in `docs/scenarios.yaml` assert `stdout matches level=ERROR` and there is no `stderr matches` step at all — and every `scripts/` program also appends to the Task's shared log under `docs/history/task_logs/`, each record carrying `tool` and `run`. One shared file is safe because `logging` writes one `disk.Append` per record and `disk` holds the PARENT directory for it; `state.TaskLog` names it from the `log` key, which `state.Init` drops, so the log lives one Task and the previous one survives on disk. `run` is a per-process id and is what makes the shared file parseable — merge's fix agents spawn `gates` as a SEPARATE process into the same file, so `scripts/report` filters to one `run` before folding or the tree is corrupt, not merely cluttered. `logging.Install` still creates the file up front — E2E-019 reads an engine log with zero records, so a missing one is not an empty one; the no-Task fallback is therefore a NAMED `no-task.json` rather than a random stem, or every fresh Task would strand one. The engine passes no `tool`, which keeps its log shape provably unchanged — its message strings and attribute keys are frozen, since `pkg/testkit/reporter` folds turns on seven exact messages and renaming one breaks the report with nothing going red. The fourth channel is `pkg/shell`, every subprocess this repository spawns and the only importer of `os/exec` (ADR 0005) — reached through `pkg/cli/<tool>`, which depguard's `spawn-shell` list makes the only importer of `pkg/shell` — no named-file exemptions, because the `bash`/`cp`/`ps` escape hatches are gone (ADR 0005, re-amended: a wrapper is judged by what its CALLERS hold, so `bash -c` became `spec.Phase`, `ps` a package that parses its own columns, and `cp -R` no spawn at all — `disk.CopyTree`). A wrapper exports OPERATIONS, never `Run(args...)`: the generic entry points are unexported, so `github.SquashMerge`/`git.HasStagedChanges`/`yamale.Validate` is the shape, and a caller keeps only its report spans, stop policy and prompts. Two entry points: `Run` for the ~35 sites that spawn-wait-read, `Start` for the six that cannot (a bidirectional JSON protocol, supervised process groups, a byte-exact stdio proxy, a long-lived server). Nothing there terminates the process — a non-zero exit is `Result.Code`, and the three `sh()` copies it replaced disagreed silently about whether one stops the run. `Env.Blank` is not `Env.Strip`: blanking leaves the key present and empty, stripping removes it, and `claudecli` strips `CLAUDECODE` so a nested `claude -p` looks entirely unlaunched-from-a-session. `_test.go` is exempt from the `os/exec` deny, because several tests exist to synthesise the raw behaviour `shell` abstracts. `pkg/disk` is every filesystem read *and* write, each a short `flock` on the target's parent around open-do-close, whole-file writes via temp+rename (`docs/adr/0003`). Gotcha with teeth: `disk` wraps its errors, and `os.IsNotExist` does not unwrap — an absent file is `errors.Is(err, fs.ErrNotExist)` now, and the old check silently reports false. The gotcha that shapes the gate: **forbidigo matches identifiers, never call expressions** — it never sees an argument, so banning `os.Stdout|Stderr|Stdin` is what catches `cmd.Stdout = os.Stdout` and makes banning `fmt.Fprint*` unnecessary, leaving `fmt.Fprintf(&buf, …)` string building untouched. `depguard` carries the rest: stdlib `log` as `pkg: "log$"` (the `$` is load-bearing, since depguard matches by prefix and a bare `log` would deny `log/slog`), and `pkg/console` denied to `scripts/**` outright — four files are exempt and each holds a descriptor, not a print: one command's stdin and three that wire a child's streams. The hook's stdin and verdict left that list when `pkg/claude/hooks` took both descriptors (docs/adr/0006), which is what a protocol package owning its own channel buys. Four more lists hold the SHAPE of the tree rather than a channel: `hex-domain` (the domain imports neither `infrastructure`, `app`, `adapters` nor `cmd` — a port that names its own implementation is a seam that breaks nothing), and `root-pkg-floor`/`root-services`/`root-scripts` (`pkg/` imports no root, product code imports neither the tooling nor the tests, tooling shells out to the binary rather than linking it). Go's own `internal/` rule already blocks part of that by accident, which is why the tree was clean; the lists cover what it does not. `root-pkg-floor` negates `**/services/**` because `**/pkg/**` also matches `internal/pkg/errors`, which is not the floor — and negates `**/pkg/testkit/**` for the opposite reason: the harness exists to import the roots it exercises (ADR 0008), so it is the one package under `pkg/` whose dependency direction is inverted. What golangci-lint cannot reach at all, `.alint.yml` does: it is text-level and tag-blind, so it sees the `// Code generated` files `generated: lax` skips and the sentinel-fenced trees `./...` never lists. `pkg-is-the-declared-channels` allowlists which packages `pkg/` may hold — the list is the decision record, and its message demands an ADR — so the fourth root cannot become a parking lot. `go-no-platform-filenames` bans a GOOS/GOARCH filename suffix and `go-no-legacy-build-tag` the pre-1.17 `// +build` — each hides a file from every Go gate with no tag for `go-build-tag-allowlist` to catch, verified by a planted `*_windows.go` that drew zero issues from golangci-lint while compiling into the binary. Deliberately unbanned: `os.Stat`/`os.ReadDir`/`os.Symlink`, which move no bytes. Where the gate cannot reach: the sentinel-fenced trees, which golangci-lint never lists, and the `// Code generated` files `generated: lax` skips. NOT the `bdd`-tagged tree — `run.build-tags: [bdd]` loads it, verified by planting a denied import in `tests/bdd-cli/scenarios/scenarios.go` and watching depguard fire. Everything else is an inline `//nolint:forbidigo` carrying its reason: SQLite's own files, an flock fd inherited by a child, and the two handles that must outlive their call (the spawn tee, the subprocess stderr spill).

**Single entity, single file**: each Go file holds one primary entity, filename = entity name in snake_case (`GitHubService` → `github_service.go` — "GitHub" is one word). Acceptable exceptions: function/constant-only files, re-export files, closely related types, data structures bundled with their primary entity. The casing is gated (`.alint.yml`, `go-filename-snake-case`); the one-entity rule is still review.

**The ceilings are numbers, not taste** (`.golangci.yaml`, ~100 linters on `default: standard`): a function is ≤80 lines and ≤40 statements (`funlen`), cyclomatic complexity ≤10 (`cyclop`; `gocyclo` is on but unconfigured, so its default 30 never binds first). Split at the ceiling rather than arguing with it. Also on and worth knowing before you write: `gochecknoglobals` and `gochecknoinits` (no package-level `var`, no `init()` — a global needs a `//nolint:gochecknoglobals` with a reason), `mnd` (name the magic number), `varnamelen` (no `x` living twelve lines), `nonamedreturns`, `testpackage` (tests go in `package foo_test`), `exhaustive` (a switch over an enum names every case).

**Errors have three rules that interlock**: `errors.New` for a static message, `fmt.Errorf` with `%w` to wrap — `err113` forbids the middle case, a `fmt.Errorf` with no argument to interpolate. (A `forbidigo` pattern claimed that job for a long time and never once fired: forbidigo cannot see a call's arguments. It is gone.) `wrapcheck` wants every error crossing a package boundary wrapped, and exempts `internal/pkg/errors` because that package already wraps. `err113` (no dynamic errors) is lifted in `_test.go`, where fixtures make them freely.

**Struct tags are snake_case both ways** (`tagliatelle`: `json: snake`, `yaml: snake`) — except where the casing is somebody else's wire contract, which is what the three carve-outs in `.golangci.yaml` mark: `adapters/github/`, `models/thread.go` (GitHub's camelCase API) and `infrastructure/testrunner/dto/` (`go test -json` PascalCase, `jest --json` camelCase). Match the wire there, not us.

**Whitespace is linted, and fixable**: `wsl_v5` (cuddling rules — first statement in a block may cuddle, a branch body up to 2 lines may) plus `nlreturn` (blank line before `return`). Never hand-fix these — the PostToolUse hook runs `golangci-lint --fix` over the edited file's whole package on every edit, and `go run ./scripts/cmd/alint <file>` is the same thing by hand.

**Comment budget** (`scripts/lint`, tested): ≤3 lines of prose, ≤15 of indented block scheme. Prose is argument and compresses; a comment earns length only by carrying a fact learned by observation — one a simplifier would delete with no gate going red — and that fits in a line plus its provenance (PR #, comment id). State each fact once, at the line it guards; the narrative goes to `docs/for_further/`. Exempt from the prose cap only: the doc comment preceding `package X`, which `go doc`/gopls surface on every lookup.
