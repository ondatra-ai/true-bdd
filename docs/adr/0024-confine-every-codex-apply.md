# Confine every codex apply turn to its Host project

**Library access amended by [ADR-0028](0028-architecture-declares-access.md):** generated profiles now grant only exact architecture-declared Go libraries, their downloaded build graph and version metadata. The engine downloads them before build-code writers; no rule singles out an organization or the engine's module. The broad module-cache grants and organization exclusions below describe the original trial, superseded by ADR-0028. Claude's file tools follow the declaration; its replay and executed code remain unconfined with network, a known limit retained for model trials (Q15).

Issue #205 restores ADR-0017's project read boundary for every codex apply, resolving ADR-0023's migration blocker. It extends ADR-0021's isolation to `us refine`, `us apply`, `scen check` and `build tests`; build code retains its replay forms and recovery. The router selects confinement by apply role and codex CLI, independently of Think/Edit tool capabilities and the explicit build-code writer option. Plan and validation turns remain `-s read-only` with their previous environment. This decision does not claim their read sandbox excludes outside files.

## Profile and write roots

Every apply gets ADR-0021's private generated home, sign-in-only copy, configuration isolation, ephemeral turn, high reasoning, configured 1050000 context, named writer profile and JSON events. The provider removes authentication after preparation or execution, including failures. The configured context remains distinct from a verified prompt size; 1M is unverified. Generated homes share the denied `tmp/codex-homes` subtree. Every apply archives its JSONL evidence; only build code recovers started failures or receives canonical test-command forms. Other apply failures remain fatal.

Reads reach the Host project, ADR-0021's enumerated `:minimal` OS baseline, GOROOT and GOMODCACHE. Its ondatra-ai source/download exclusions, VCS-cache denial, scratch denials and disabled subprocess network remain. Host grants take precedence when the Host project is nested under a denied scratch root. There is no outer sandbox or weaker fallback.

Write grants derive from the execution mode's deduplicated Write/Edit/MultiEdit patterns, with SourceWriteRoots retained for callers carrying only those roots. Host `tmp/` remains writable, as in ADR-0021; HOME, TMPDIR, caches and generated runtime links stay there. Every root and scratch directory resolves inside the Host project before rooted creation. A root equal to the Host project, escaping it, or reaching the protected generated-home subtree is refused; case variants cannot override that protection. File-root parents may be provisioned without granting those parents; an existing file stays a file and an absent file is never made into a directory. Bare service roots remain directories; the mode factory preserves existing single-file roots. Build-tests uses a separate configured-pattern mode, so an absent literal filename is also kept exact instead of being interpreted as a directory.

Codex 0.162.1 rejects arbitrary wildcard write entries; it supports exact paths and subtree grants. A configured glob authorizes creating and changing exactly the files it matches, including when no matching file exists before the turn. Literal files and terminal `/**` directory subtrees retain their exact profile grants. For other patterns, the profile grants the narrowest literal directory before the first wildcard, provisions that directory safely, and the engine enforces the original patterns after the turn. `*`, `?`, character classes and recursive `**` retain their matching semantics; overlapping grants authorize their union. Newly created non-matching files are removed. A pre-existing non-matching file changed, deleted, renamed or given different permissions fails the turn with one WARN naming that file; its changed contents remain available for diagnosis. Enforcement also runs after failed turns, and these violations are fatal even for build code's recoverable writer. This is a post-turn boundary: a non-matching file under the granted directory can be changed during the turn. Generated homes remain denied and excluded from the comparison. A pattern whose literal directory is the Host project itself, a protected home or outside the Host project is refused; malformed patterns and symlink escapes also refuse.

## Runtime exceptions

All command subprocesses still inherit no environment. Go retains GOROOT/bin, the system executable directories, offline proxy/sumdb, local toolchain, disabled telemetry/CGO, host caches and `-trimpath -buildvcs=false`.

Installed node, npm, its npx companion and docker are optional, discovered on the engine's PATH. Their resolved executable paths become explicit read grants, and host-scratch runtime-bin links make their names available without inheriting the user's PATH. npm and npx additionally read their own installed npm package only when their resolved `bin/npm-cli.js` or `bin/npx-cli.js` belongs to a root whose `package.json` names `npm`. The package root must not overlap the Host project, the authentication home, or the user's sensitive `.codex`, `.claude`, `work`, `.ssh`, `.aws` and `.config` roots, including their ancestors. An unsafe or unverifiable JavaScript package is refused with a WARN and no runtime link or read grant. The npx command is required by declared Jest and Playwright replay forms; it uses the same offline npm policy. Mach-O images are inspected through Disk access to enumerate their linked non-system libraries recursively; the profile names those library files, containing library directories and installation symlinks. Homebrew's `/opt/homebrew/opt` or `/usr/local/opt` directory is granted only when a dependency uses it: dyld needs to read installation-link metadata there. Unrelated canonical Cellar targets remain denied. No entire Cellar, home directory or work tree is granted. Other binary formats retain their executable grant and the OS baseline; non-macOS runtime dependencies have not been live-verified.

npm receives offline mode, scratch cache and user configuration. Docker receives scratch configuration; no daemon, Docker socket, external context, credentials, plugin directory or network endpoint is granted. Its local client works; a suite requiring daemon access must arrange that outside the apply turn. Granting a daemon that could mount arbitrary host paths would break the confinement. `OPENSSL_CONF=/dev/null` prevents Node from loading external OpenSSL configuration. Runtime presence is not a promise of package downloads, network servers or container creation inside the sandbox.

## Evidence and recording

The common apply boundary is probed for every command with real `codex sandbox -P writer`: work trees, codex sessions, Claude transcripts, generated authentication, sibling scratch, excluded module source/downloads and VCS copies are unreadable; neighboring writes and a Node socket connection fail. Directory, existing and missing single files, configured globs and scratch writes succeed. Selected Go replay, node, npm and the Docker client run. ADR-0021's sequential-home and missing-service probes remain green. These sandbox probes use dummy credentials and harmless markers without a model call.

Two Scenarios exercise real codex apply turns: a us-refine closure fix edits the scratch product document, and build-tests writes step definitions beneath an explicit configured recursive root. The original duplicate-collapse Scenario is recorded first without weakening its outcome. Generated homes and runtime scratch are excluded before run and per-call snapshot traversal, so neither authentication nor runtime symlinks enter recordings. Other recording files remain byte-identical except fixtures explicitly recorded for changed requests.
