# Build code repairs the failing set and the engine answers its verdict

One `build code` Item is the whole failing set from discovery, or no Item when discovery is green. Its `tests-pass` D: Prompt uses the latest runner verdicts through the existing built-in check path (ADR-0015); no validation model mirrors a boolean. A singleton retains its original test identity and per-test behaviour.

## Considered Options

- One repair per test: repeats whole-service investigation and code handoffs for shared failures.
- One writer without a plan: removes the person's existing apply, refine or exit choice.
- A validation model: pays for a verdict the runner already owns.

## Consequences

The fix turn proposes one plan naming changes, files and served tests. The writer gets the same set, grouped failure evidence, every matched Scenario and its steps, deduplicated catalogue phrases and words, Specification paths, service edit roots and ADR-0018's crush-only command forms. It reads the Specification and harness, implements the service, tests each part and all set members, then reports changes and observed passes. Neither turn states a time, turn, token or cost budget. The default writer is crush, which runs without the router deadline and stops with the command. Claude retains its 20-minute bound; claude and codex receive no test-command grant.

Every completed apply, including applied false and the terminal attempt, triggers one engine runner start in the post-apply hook. Member selectors form an alternation; Go package build failures and Playwright startup failures make it unfiltered. An ordinary member needs its own passing result; a missing or skipped member stays failing with a did-not-run finding. Passing members leave and grouped evidence is rebuilt. Equal normalized output groups evidence, without claiming a shared cause. The walker counter and outer bound stay unchanged; shrinking the set does not reset attempts. Fresh outer discovery catches regressions outside the previous set, and the person's exit ends the Item.
