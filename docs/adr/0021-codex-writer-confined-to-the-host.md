# Confine the codex build-code writer through its own permission profile

Only `build code --fix`'s codex apply turn uses a generated per-turn `CODEX_HOME` and named `writer` permission profile. This amends ADR-0018 and ADR-0019's codex exceptions and ADR-0020's original provider restriction. Other commands and roles retain their exact sandbox arguments, inherited environment, prompts and failure handling. No outer `sandbox-exec` is used: nesting a Seatbelt profile under codex's fails.

## Boundary

The generated home is `{host}/tmp/codex-homes/{run_basename}/{label}-codex-home`, created private. Only `auth.json` is copied from the original `CODEX_HOME` (or `~/.codex`); configuration, sessions, history, models cache, skills and AGENTS.md are never copied. Codex itself may create runtime state there. Every writer profile denies commands access to the shared `{host}/tmp/codex-homes` subtree, protecting all turns and runs even under writable host tmp. The provider removes `auth.json` when preparation or the turn ends, on success and failure; cleanup errors are reported. Recording filters this home and codex shell/build scratch out of cassettes, including refreshed authentication.

The profile starts restricted, with no `:root` grant or inherited built-in workspace profile. The host root is readable; declared service edit roots and host `tmp/` are writable. Existing symlinks resolve before edit roots are accepted; a root escaping the host, including a scratch-root symlink, is refused before spawning. The profile resolves symlinks at enforcement too, so a link inside the host does not expose an outside target. A narrower host grant wins over a broader scratch denial, allowing hosts nested under those scratch paths.

Before spawning a confined writer, the engine creates every absent service edit root with its missing parents inside the host and logs each created root once at INFO (`Codex edit root created`, `path`). Rooted filesystem operations refuse symlinks escaping the host during creation, including dangling parents and concurrent symlink replacement; edit roots resolving outside the host are refused. Existing roots are left in place without a creation log. This provisions an empty service when a cut has no `services/` at all. The profile grants stay unchanged: the writer can write inside the edit roots and host tmp, and cannot create other entries at the host root.

The only external reads are these runtime/toolchain exceptions:

- `:minimal`, codex-cli 0.162.1's macOS OS runtime baseline: `/bin`, `/sbin`, `/usr/bin`, `/usr/sbin`, `/usr/libexec`, `/usr/lib`, `/usr/share`, `/opt/homebrew/lib`, `/usr/local/lib`; `/Library/Apple`, `/Library/Filesystems/NetFSPlugins`, `/Library/Preferences` (including Logging); `/var/db` and `/private/var/db` (including directory records, timezone and eligibility); `/etc` and `/private/etc` (including passwd, master.passwd, protocols, services and localtime); system framework, private framework and subframework trees under `/System/Library`, `/System/iOSSupport/System/Library` and `/Library/Apple/System/Library`, system extension executable mappings, CoreServices version files and `/Library/Apple/usr/lib`.
- The same OS baseline's root-directory and firmlink-parent metadata, `/dev` metadata, random/urandom, autofs_nowait, null/zero, fd and terminal handles, dtracehelper, system runtime Mach services, sysctls and the syslog socket. Device handles have codex's normal runtime writes. These are OS facilities, not writable project directories. No TCP/IP network grant is given.
- The installed `GOROOT` and populated `GOMODCACHE`, resolved through `go env -json GOROOT GOMODCACHE`. Both `GOMODCACHE/github.com/ondatra-ai` and `GOMODCACHE/cache/download/github.com/ondatra-ai` are explicitly denied, excluding source and download archives. `GOMODCACHE/cache/vcs` is also denied in full, since its bare repositories can contain the excluded source and offline commands have no use for them. Go build caches are placed inside host tmp.

The generated profile names `:minimal` and documents its expansion in comments; codex owns those OS rules, including executable mapping and IPC rules that path entries alone cannot express. Its implicit `/private/tmp` and `/private/var/tmp` scratch reads and writes are explicitly denied. All other outside paths, including work trees, sibling cuts, codex sessions and claude transcripts, receive no read or write grant. Live probes used harmless markers in a sibling scratch tree and harmless existing OS files; no secret or historical session content was read.

Writer commands inherit no environment. The profile sets PATH to GOROOT/bin and system executable directories; HOME, TMPDIR and GOCACHE inside host tmp; GOROOT/GOMODCACHE; GOPROXY=off, GOSUMDB=off, GOTOOLCHAIN=local, GOFLAGS='-trimpath -buildvcs=false', GOTELEMETRY=off and CGO_ENABLED=0. This Go-focused trial does not grant other language runtimes or require CGO. Network is disabled for subprocesses, including tests and any engine they build. Codex's own model connection remains available.

## Turn and evidence

The generated configuration selects `approval_policy=never`, disables web search, apps, plugins, multi-agent, memories, shell snapshots, login shells and host skill discovery. `project_doc_max_bytes=0` suppresses AGENTS.md discovery. A fresh home has no project trust or user MCP configuration; `--ignore-rules` suppresses execpolicy files. The turn remains `--ephemeral`, uses `--strict-config --json`, and replaces `-s` with `default_permissions=writer`. Unsupported profiles/configuration have no weaker fallback. The boundary is calibrated with real codex-cli 0.162.1 on macOS; other platforms have not been live-verified.

Only this writer receives the canonical whole-suite and selected replay forms with codex process polling instead of the retired job tool. Its final message still arrives through `-o`. Stdout JSONL is archived as `{label}-codex-events.jsonl`, separately from stderr; the transcript holds both. Drill audit reads command_execution and file_change events, retains raw evidence and never infers that a referenced read succeeded. Malformed evidence is reported; encoded or computed shell paths remain an audit limitation.

High reasoning and a 1,050,000-token context window are configured for the trial's `codex:gpt-6.1-sol`. Successful parsing does not establish capacity or account entitlement. A verified window is the largest actual successful prompt measured in the turn's own input token counts; 1M is not verified by this change.

A started codex writer exiting non-zero (including usage limits), returning whitespace or leaving no answer file carries a distinct started-turn outcome. Build code retains edits, counts the attempt, logs one WARN and runs PostNotApplied. Tests decide the next failing set. Start failures and engine refusals before spawn remain fatal. No codex response watch is added; existing codex request timeouts apply and the engine wrapper retains its unbounded whole turn.

## Recordings and request portability

The former workspace-write `build-code-fix-by-codex` fixture is re-recorded with real codex for the writer flags and replay command forms. Replay always validates the recorded request hash without migrations. Other existing recordings remain byte-identical; the two new fixtures exercise confined codex writers.

Toolchain roots, module cache, codex executable resolution and generated CODEX_HOME live only in configuration or environment, outside the request hash's argv and stdin. Host and artifact paths in requests use the harness's existing CWD, HOME and run-directory normalization. Regression checks compare writer request hashes with relocated toolchain, binary and authentication paths. Fixture extensions preserve the shipped template prefix, including provider-specific completion wording.
